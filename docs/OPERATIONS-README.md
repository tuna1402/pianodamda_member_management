# 피아노를 담다 — 디자인·실제 통계·실행 감시 v0.10.1

2026-10-04 서버 보완: HOST 기본 loopback 유지/명시 바인딩, 공개 health/readiness, 원장 전용 작업 실행 감시, worker 실패/회복/지연과 정상 종료 drain을 추가했다. [SERVER-RUNTIME.md](SERVER-RUNTIME.md)의 환경·검수·동기 모의 worker 한계를 확인한다. v0.10 소스 ZIP은 이 보완 전 기록이며 최종 배포 준비본은 v0.10.1로 구분한다.

2026-10-04: 검토한 회원/운영자/로그인 디자인을 실제 앱에 적용했다. 원장 통계는 실제 서비스 DB의 확정 일정·완료 수업·현재 전체 모의 알림을 집계한다. 최근 7일/28일 전환과 SVG 차트·숫자 표, 회원의 과제 우선 홈·피아노 이미지, 로그인 이미지와 관리 화면 공통 디자인을 제공한다. 디자인 시안의 예시 숫자는 앱에 넣지 않았다. 격리 미리보기의 데이터는 별도로 작성한 합성 검사 자료다.

현재 검수 미리보기는 http://127.0.0.1:4193/ 이며 `work/service-design-preview.sqlite`를 사용한다. 아래 v0.9의 4190 미리보기는 이전 검수본으로 유지했다. 실제 권한·공개·일정·알림·보존 규칙은 유지한다. 통계와 파일 제공 규칙은 [DESIGN-STATISTICS.md](DESIGN-STATISTICS.md)에 있다.

## 기존 운영 확장 v0.9 안내

원장 대시보드, 상담·체험·수업 일정관리, 반복 일정, 모의 자동 수업 알림을 추가한 개발 검수본이다. 실제 문자업체 연동·학생 데이터 이관·공개 배포는 완료되지 않았다.

## 실행

Node.js 24 이상에서 구현 폴더의 `npm start`를 실행한다. 기본은 새 합성 데이터로 시작하는 개발 모드다. 기존 서버와 다른 포트와 DB 경로를 사용한다.

```powershell
$env:PORT='4192'
$env:DB_PATH="$PWD/data/operations-demo.sqlite"
node server.mjs
```

검수 중인 미리보기는 http://127.0.0.1:4190/ 이고 DB는 구현 폴더 외부의 격리 work 경로에 있다. 소스 묶음에는 DB를 포함하지 않았다. 위 명령으로 새로 시작하면 비어 있는 운영 일정부터 확인할 수 있다.

개발 원장: `director-demo` / `Demo-Director-2026!`. 개발 학생: `MBR-000742` / `1234`(첫 변경 필수). 모두 합성 검사 전용이다. 실제 운영 모드는 기존 원장 최초 설정과 전환 검수 절차를 요구하며 체험 계정을 허용하지 않는다.

## 사용 흐름

1. 원장으로 로그인하면 운영 대시보드가 열린다. 기준 날짜, 상담·체험·수업 건수, 알림 대기·보류·실패, 최근 변경을 확인한다.
2. 일정관리의 방문자 관리에서 미등록 상담·체험 대상을 최소 정보로 등록한다. 번호 확인은 선택한 본인/보호자의 실제 확인 여부를 기록한다. 학생 계정과 등록번호는 생성하지 않는다.
3. 상담·체험은 학생 또는 방문자, 수업은 학생과 수강등록을 선택한다. 날짜·시각·소요시간을 입력하고 임시/확정을 선택한다. 원장 단독 운영으로 종류 간 시간 겹침과 휴무를 차단한다.
4. 자동 알림 설정에서 시점·대상 종류·문구·일일 모의 접수 상한을 확인하고 모의 실행을 켠다. 기본 시점 24시간 전은 개발 예시다.
5. 확정 일정에서 알림 사용 → 미리보기 → 수신자·번호·문구 확인 → 저장한다. 서버가 10초 간격으로 예약 시각이 된 작업을 처리한다. 실제 업체 호출은 없다.
6. 날짜/시간 변경은 사유를 입력하고 다시 확인한다. 취소는 기존 대기 알림을 중단한다. 이미 접수됐거나 결과가 불명확한 문자를 취소됐다고 표시하지 않는다.
7. 주간 반복 종료일을 입력하면 회차를 미리보기한다. 휴무 등 제외할 회차의 날짜를 쉼표로 입력한다. ‘이번 회차/이후 회차’를 나누어 수정하며 충돌 시 전체 저장을 보류한다.
8. 수업 일정 상세의 수업 기록 작성/열기로 기존 관리 화면에 연결한다. 일정 확정은 수업 완료·학생 공개를 자동 실행하지 않는다.
9. 방문자가 등록 학생으로 전환하면 학생 관리를 먼저 완료하고 방문자 관리의 ‘등록 학생 연결’에서 같은 사람임을 확인한다. 학생을 추가로 생성하지 않으며 알림은 다시 확인한다.

이미 지난 알림 시각은 보류한다. 실행 지연이 5분을 초과하거나 수업이 시작된 작업도 보류한다. 이 5분은 개발용 고정값으로 실제 운영 전 확정·설정화할 항목이다. 실패 확인 건만 재시도하며 성공/결과 불명 건은 자동 재발송하지 않는다.

설정 변경은 기존 일정의 알림 확인을 보류할 수 있다. 연락처·문구·수신자·정책을 다시 검토한 뒤 일정에서 미리보기하고 저장한다. 실제 문자 비용은 표시하지 않는다.

## 검증

`npm test`: 기존 기능과 신규 운영 기능·UI의 빠른 자동 검사. 최종 66개 통과.

`npm run test:live`: 실제 시계가 예약 시각에 도달할 때 자동 모의 접수가 발생하는 검사. 약 1분 이내, 추가 1개 통과. 합성 메모리 DB에서만 실행하며 외부 호출이 없다.

두 프로세스의 같은 알림 경쟁과 서로 다른 작업의 상한 경쟁을 별도 SQLite DB에서 검증했다. 실제 업체의 중복 보장·통지·청구와 장시간 부하는 별도다. 66개+1개 검사 결과를 OP-T01~25 전체 또는 기존 T-01~41 전수 수용으로 계산하지 않는다.

## 보존과 복원

학생 파기 시 연결된 일정·알림·시도·모의 접수·변경 이력도 제거한다. 대장 정보와 분리한다. 방문자 보관 기간은 기본 미확정이다. 알림 설정에서 보관일과 정책 확인을 입력한 후 마지막 일정 종료/등록일 기준으로 별도 파기한다. 삭제 목록을 복원에 재적용하며 복원 후 자동 알림은 꺼지고 대기 작업은 재검토한다.

기존 인증·초기 이관·암호화 백업·대장 정책 절차는 기존 README와 운영전환_준비서를 참고한다. 새로운 방문자/문자 보관 목적·기간과 업체 사본 처리는 실제 운영 전에 검수한다.

## 실제 문자 연결

모의 어댑터는 `sms-provider.mjs`, 실행/예약 규칙은 `operations.mjs`에 있다. 업체 선정 후 실제 비동기 어댑터와 접수/전달 조회, 통지 검증, 문자 종류·비용·상한을 개발한다. `examples/sms-connection-review.json`은 검토 양식이며 활성화 설정이 아니다. 운영 모드에서는 현재 업체 미연결 알림이 보류된다.

월간 달력, 자동 변경·취소 안내, 직접 일괄 문자, 자동 보강, 광고 발송은 추가하지 않았다. 전체 키보드·스크린리더·실제 200% 확대·실제 업체/호스팅 검수는 남아 있다.
