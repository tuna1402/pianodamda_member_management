# 서버 실행·감시·정상 종료

2026-10-04 KST · v0.10.1 배포 전 로컬 검수 보완

## 설정

`HOST` 기본값은 `127.0.0.1`이다. 같은 호스트의 HTTPS 프록시 뒤에서는 이를 유지한다. 컨테이너 플랫폼이 공개 바인딩을 요구할 때 담당자가 `0.0.0.0`을 명시한다. `localhost` 또는 유효한 IP만 허용한다. `PORT`는 0~65535 정수(0은 격리 검사 자동 포트), `SHUTDOWN_GRACE_MS`는 1000~60000 정수이며 기본 10000ms다. 환경 예제는 서버가 자동으로 읽지 않으므로 실제 실행 환경에서 주입한다.

기존 `APP_MODE=production`, 정확한 HTTPS `PUBLIC_ORIGIN`, Secure 쿠키, 체험 계정 금지, 최초 원장/운영 전환/복원/무결성 검수를 유지한다. HOST를 변경해도 운영 검수 게이트가 해제되지 않는다. 외부 API 어댑터는 아직 없고 실제 문자 발송은 보류된다.

## 공개 상태 점검

- `GET/HEAD /healthz`: 프로세스 응답 상태. 정상은 200 `{status:"ok"}`, 종료 중은 503이다.
- `GET/HEAD /readyz`: HTTP 수신·DB 읽기·두 주기 작업 상태를 함께 확인한다. 정상 200, 준비 미완료/작업 실패·지연/종료는 503이다.
- 공개 응답은 상태와 DB/worker 정상 여부만 포함한다. 계정·이름·연락처·DB 위치·키·업체·오류 원문·정확한 실행 이력을 포함하지 않는다. 응답은 저장 금지다. 지원하지 않는 메소드는 405다.

readiness는 실제 문자가 전송될 수 있다는 뜻이 아니다. 업체 미연결 상태에서 알림 작업이 정상적으로 보류 규칙을 적용하는 것도 worker의 정상 실행이다. 학생·대장 정보 정책 검수나 백업 사본 최신성을 readiness가 대신 증명하지 않는다.

## 원장 전용 작업 감시

`GET /api/admin/runtime`은 기존 일반 원장 세션만 허용하며 시작 시각, 작업별 간격·마지막 시도/성공·연속 실패·진행 여부·정상/미시작/실패/지연/중단을 반환한다. 초기 제한 세션·일반 학생은 거부한다. 오류 원문과 DB 경로는 포함하지 않는다. 현재는 원장 전용 조회 API이며 화면 알림이나 외부 감시 서비스는 별도 연결 대상이다.

알림 10초, 파기 60초 주기는 유지하고 서버 시작 시 처음 한 번 실행한다. 같은 작업이 진행 중이면 겹친 호출을 건너뛴다. 성공 때만 마지막 성공 시각을 갱신하고 실패 뒤 다음 성공 시 상태를 회복한다. 마지막 성공 후 간격의 3배를 초과하면 지연으로 판정한다. 실행 실패 로그에는 고정 작업 이름만 기록한다.

## 정상 종료

SIGINT/SIGTERM 핸들러는 재진입해도 같은 종료 작업을 사용한다. 먼저 readiness를 내리고 예약 timer를 중단한다. 새 API 요청은 거부하고 HTTP 수신을 닫으며 유휴 연결은 정리한다. 이미 진행 중인 요청은 DB를 사용할 수 있도록 끝까지 기다리고 응답 뒤 연결을 닫는다. grace 안에 끝나지 않는 HTTP 연결은 강제로 정리하고 종료 코드는 실패로 표시한다. 요청과 진행 중 worker가 끝난 뒤 SQLite 연결을 닫는다. 최신 삭제 목록은 붙어 있는 별도 DB 파일로 계속 유지한다.

**현재 알림/파기 worker는 동기 SQLite·모의 처리다.** 미래의 실제 비동기 업체 호출이 끝나지 않으면 진행 중 worker Promise를 기다리는 부분에는 독립 timeout이 없으므로 정상 종료가 지연될 수 있다. 업체 어댑터 도입 때 요청 timeout·취소/조회·불명 결과 보존과 종료 상한을 함께 설계해야 한다. 현재 DB를 사용 중인 worker를 두고 임의로 DB부터 닫지 않는다. 외부 프로세스 감독자의 강제 종료는 정상 drain으로 표시하지 않으며 재시작 후 결과 확인·무결성을 검수한다.

프록시의 `X-Forwarded-For`를 현재 무조건 신뢰하지 않는다. 로그인 실패 제한은 socket 주소 + 계정 기준을 유지한다. 같은 호스트의 프록시로 이용자 주소가 묶이는 문제는 실제 배포 때 명시적 신뢰 프록시 범위로 보완할 후속 항목이다.

## 검사 범위

`runtime-test.mjs`는 설정 거부, worker 실패/회복/지연·겹침, 진행 중 요청/worker 완료 전에 DB 사용 유지, 중복 종료, grace 초과 연결 종료, 실제 별도 Node 프로세스의 바인딩·health/readiness·원장/학생 권한·위조 프록시 헤더·DB 보존/재시작을 검사한다.

Windows에서는 OS의 SIGTERM 전달이 Unix와 달라 별도 실제 Node 프로세스에 종료 입력을 주어 Node의 SIGTERM 이벤트/실제 종료 핸들러를 실행했다. Unix에서는 실제 `kill(SIGTERM)` 경로를 사용하도록 검사를 작성했지만 이번 Windows 결과를 Linux OS 신호 전수 검증으로 표시하지 않는다. Linux 배포 환경에서 systemd/컨테이너가 보내는 실제 신호와 grace 시간도 다시 검수한다.
