## 운영 도구 사용 순서

ops.mjs는 대상 DB_PATH를 명시해야 한다. 명령 중 실제 원장/실제 개인정보를 처리하는 실행은 운영 준비 결과 검수와 별도 승인을 마친 뒤 담당자가 수행한다.

| 명령 | 입력·결과 | 용도 |
|---|---|---|
| init-director | 표준입력JSON id/password, 16~128자, 기존 원장 있으면 거절 | 새 운영DB 최초 원장 설정 |
| recover-director | 표준입력JSON id/password/method, 기존 세션 폐기 | 승인된 오프라인 본인확인 분실복구 |
| preview-import 자료.json | source/batch/cutoff와 정규화된 학생/상품/수강/수업 배열 | 원본 스냅샷 매핑 검수 |
| apply-import 자료.json | 검수 통과 배치만 원자적으로 저장, 계정 자동 활성화 없음 | 초기 확정 이관 |
| rollback-import 배치ID | 운영 전·수정/외부 연결/계정 활성화 없을 때만 가능 | 운영 시작 전 되돌림 |
| check | DB 무결성·참조·번호·기간 중복 확인 | 배포/복원 검수 |
| purge | DB 기한 처리, 외부 사본 미검수 표시 | 정기 작업·재시도 |
| backup 새파일.pdmbak | 표준입력JSON 32바이트hex key, 암호화 | 백업 생성 |
| restore 백업.pdmbak | 표준입력key, 새 DB_PATH, 최신 RETENTION_JOURNAL_PATH | 격리 복원·인증 폐기·삭제 재적용 |
| begin-operation 검수.json | 6개 검수 항목 approved/evidence, 실제 원장/무결성 필요 | 이관 잠금 및 운영 상태 전환 |

키·비밀번호를 명령줄 인자로 입력하거나 이 문서에 기록하지 않는다. 표준입력은 운영 담당자의 안전한 입력 환경에서 제공한다. 로컬 임시 DB 파일이 백업 과정에 잠깐 생성될 수 있으므로 작업 디렉터리의 OS 접근권을 제한한다. Windows 파일ACL·백업 키 저장·파기 기한은 운영 담당자가 검수해야 한다.

삭제 목록은 기본적으로 DB_PATH 뒤에 `.deletions.sqlite`를 붙인 별도 DB이며 RETENTION_JOURNAL_PATH로 지정할 수 있다. 데이터 DB 백업과 함께 과거로 되돌리지 말고 최신 원본을 별도 접근 제한·복제 정책으로 관리한다. 도구가 임의 사본이 최신임을 외부적으로 증명하지는 못한다. 다른 데이터셋이나 백업 시점보다 삭제 건수가 적은 목록은 거절한다. DB 밖 원본/내보내기/기기 사본의 파기는 별도 검수다.

## 이관 준비 한계

예제 JSON은 Google Sheets를 직접 읽는 커넥터가 아니라 승인 매핑으로 정규화한 스냅샷 형식이다. 실제 시트 접근·변환·이관은 실행하지 않았다. 최초 검수 형식은 v1.1/헤더4행을 명시하고 탭ID와 파일 식별자를 받는다. 실제 승인 원본과의 일치는 담당자가 대조해야 한다. 수강 시작·관리 구분·완료 불명확 보강은 추정하지 않는다.

현재 확정 이관 도구는 재원/휴원 학생과 유효/휴원 등록을 지원한다. 종료생·보존 예외·다른 원본 버전은 자동 이관하지 않고 별도 검수 대상으로 둔다. 웹 입력이 생긴 배치의 되돌림은 거절하며 별도의 신규 입력 보존 복구가 필요하다.

## 실제 출시 전에 남은 조건

1. 실제 대장 항목·기산일·근거·개인과외 처리·고지/필요 동의·미성년 처리 검수. 현재 대장은 합성 정책이며 준비 완료로 표시하지 않는다.
2. 인증 만료 수치·본인확인 방법·실패 제한·원장 복구 담당, 번호 이력/삭제 목록/작업 로그의 보존 목적·기간을 확정한다.
3. 도메인/호스팅/예산/제공자·저장 위치/운영 담당을 선정하고 실제 HTTPS·프록시·OS 접근권·프로세스 재시작·감시·파기 실패 알림을 검증한다. 현재 로컬 코드와 운영 도구만 준비했다.
4. 백업 복구 목표·기한·키 관리·최신 삭제 목록 복제·DB 밖 사본 처리를 검수한다. 단일 인스턴스를 운영 기준으로 두며 다중 서버 배포 검증은 별도다.
5. 전체 접근성·200% 확대·부하/장시간 운영, 실제 매핑과 수용 시나리오의 외부 의존 부분을 검수한다. 29개 테스트를 41개 시나리오 전수 통과로 표시하지 않는다.
6. 실제 이관·실제 계정 설정/전달·유료 계약·외부 공개는 준비 결과와 비용/책임을 확인한 뒤 필요한 승인 범위에서 실행한다.

## 환경 선택 검토표

| 선택지 | 확인해야 할 조건 | 현재 상태 |
|---|---|---|
| 단일 서버 + SQLite + 같은 호스트 HTTPS 프록시 | 동시 쓰기 규모, 파일 접근권, 디스크 백업, 재시작/감시 담당 | 현 구현과 가까운 검수 후보, 외부 배포 미실행 |
| 관리형 앱 + 영속 저장소 | 디스크 영속성, 인스턴스 수, 프록시/쿠키, 백업·복원 가능성 | 제공자/요금/데이터 위치 미선정 |
| 다중 앱 인스턴스 + 공유DB | DB 이식, 원자적 인증/번호, 파기 작업 중복 방지, 비용·운영 책임 | 필요성 확인 후 별도 설계·검증 |

현재 가격이나 제공자 기능을 검증·추천한 표가 아니다. 실제 환경 선정 시 해당 제공자의 최신 사양·요금·데이터 처리 조건을 확인한다.
