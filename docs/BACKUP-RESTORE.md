# 백업·격리 복원·롤백

2026-10-04 KST · 기존 운영 도구의 사용 조건을 정리한 안내다. 실제 운영 DB·백업·키는 반입하지 않았다.

| 명령 | 필요한 값 | 결과와 제한 |
|---|---|---|
| `node ops.mjs check` | 명시한 `DB_PATH` | DB 무결성·관계 확인. 대상 DB 존재 필요 |
| `node ops.mjs backup 새파일.pdmbak` | DB 경로, 표준입력 JSON `key` | SQLite backup API 사본을 AES-256-GCM 암호화. 새 파일만 허용. 삭제 목록은 포함되지 않음 |
| `node ops.mjs restore 백업.pdmbak` | 존재하지 않는 새 `DB_PATH`, 최신 별도 삭제 목록 경로, 표준입력 `key` | 데이터셋·삭제 건수 대조, 삭제 재적용·세션 폐기·관계 검사. 복원 후 알림 꺼짐/대기 보류 |
| `node ops.mjs purge` | 명시한 DB 경로와 확인한 보관 정책 | DB 보관 작업. 업체/기기/내보내기 사본은 별도 검수 |

키는 32바이트 hex 형식이며 안전한 표준입력으로 주입한다. 키·비밀번호를 명령줄 인자·저장소·기록에 남기지 않는다. 백업과 키의 접근·보관을 분리한다. 임시 평문 scratch 파일이 생성되므로 백업 작업 디렉터리 접근도 제한한다.

**최신 삭제 목록은 데이터 백업과 별도 관리한다.** 현재 backup은 이를 포함하지 않는다. 도구는 데이터셋과 건수를 확인하지만 운영자가 전달한 사본의 최신성을 외부적으로 증명하지는 못한다. 기기/업체/이관 원본 사본도 별도 파기/접근 정책이 필요하다.

1. 코드 버전·설정·스키마 변경을 고정하고 합성 환경에서 검사한다.
2. 변경 시간 신규 입력/worker 처리 중지 방식을 검수한다. v0.10.1은 정상 종료와 원장 감시 API를 추가했다. 실제 Linux 신호·플랫폼 grace·미래 비동기 업체의 종료 상한은 별도 확인한다.
3. 일관성 있는 암호화 DB 백업과 최신 삭제 목록 별도 사본을 서버 외부에 보관한다. 실제 복원 시 키 접근도 확인한다.
4. 신규 코드/검수한 스키마 적용 후 무결성·기능·알림 상태·HTTPS를 확인하고 제한 재개한다.
5. 장애 시 호환되는 이전 코드로 복구하거나 새 격리 DB로 복원한다. 기존 운영 SQLite 위에 과거 파일을 직접 덮어쓰지 않는다.
6. 복원에 최신 삭제 목록을 재적용하고 세션 폐기·알림 꺼짐/보류, 이후 신규 입력과 접수/결과 불명 문자의 상태를 대조한 뒤 재개한다.

코드 롤백과 데이터 롤백은 같지 않다. 스키마가 이전 코드와 호환되는지, 백업 이후 입력을 어떻게 보존할지, 이미 접수된 문자의 중복을 어떻게 막을지 먼저 결정한다. RPO/RTO, 백업 주기·보관일·키 담당자는 실제 운영 전 확정한다. [기존 전환 준비서](운영전환_준비서.md)의 실제 정책·증적 요구를 함께 검수한다.
