# 자동 수업 알림 — 문자업체 연결 준비서

2026-10-03 · 현재 상태: 모의 발송 구현·검사 완료, 실제 업체 미선정

날짜별 확정 수업에 알림을 예약하고 서버에서 자동 처리하는 흐름을 구현했다. 실제 업체 연결은 선택한 업체의 인증·접수·조회·비용 규칙을 확인한 다음 추가한다. 현재 프로그램은 외부 문자 API를 호출하지 않으며 운영 모드에서도 미연결 발송을 보류한다.

## 비교할 후보

두 후보의 공식 문서를 확인했다. 아래는 연결 검토 자료이며 계약·최종 추천·요금 확정이 아니다. 기존에 사용하는 업체가 있다면 그 업체를 먼저 검토한다.

| 후보 | 공식 문서에서 확인한 기능 | 연결 시 확인할 항목 |
|---|---|---|
| SOLAPI | 문자 발송 API, 발신·수신 번호와 본문, 문자 종류의 자동 판정 옵션 | 계정 인증, 발신번호 등록, 접수 결과 조회, 응답 유실 시 요청 추적, 실제 단가와 보관·결과 통지 조건 |
| 네이버 클라우드 SENS | 콘솔/API 문자발송, 발송 이력과 결과 조회, 발신번호 등록과 이용 한도 설정 | 프로젝트·인증키 설정, 접수와 단말 결과 구분, 실제 단가·상한, 조회 및 보관 조건 |

SOLAPI 기능 근거: [메시지 발송](https://solapi.com/developers/api/messages), [단문 문자 메시지](https://solapi.com/developers/api/messages-sms). 네이버 클라우드 SENS 기능 근거: [SMS 발송·조회 가이드](https://guide.ncloud-docs.com/docs/sens-smsmessage).

문자 길이는 단순 글자 수로 비용을 확정하지 않는다. SOLAPI 단문 문서는 90byte 기준과 한글/영문 계산을 안내하고, SENS 가이드는 SMS와 LMS/MMS의 길이 제한을 구분한다. 업체 선택 후 실제 템플릿에 대해 해당 업체 규칙으로 종류와 비용을 산정한다. 현재 화면의 비용은 ‘미확정’이다. [SOLAPI 길이 기준](https://solapi.com/developers/api/messages-sms), [SENS 길이 기준](https://guide.ncloud-docs.com/docs/sens-smsmessage).

## 연결 작업 묶음

1. 업체·계정·등록 발신번호와 지정 테스트 수신번호를 확정한다. 비밀키 원문은 채팅이나 공개 설정 파일에 넣지 않고 서버 비밀 설정으로 전달한다.
2. 목적별 수신 대상과 필요한 고지·동의·거부 처리, 업체 데이터 처리·보관 조건을 검토한다. 상담·체험 대상은 학생 연락처와 별도 검토한다.
3. `sms-provider.mjs`의 모의 구현 옆에 업체별 발송/조회 어댑터를 추가한다. 실제 호출은 서버 실행기에서만 수행한다. 비밀값·연락처·본문을 일반 로그에 남기지 않는다.
4. 접수 전 요청 키, 요청 추적 값, 업체 메시지 ID를 연결한다. 업체의 중복 요청 보장 범위가 불명확하면 응답 유실 건을 ‘결과 확인 중’으로 두고 조회 또는 수동 대조한다. 앱의 작업키만으로 외부 발송 1회를 보장한다고 표시하지 않는다.
5. 접수 성공과 전달 성공을 분리한다. 결과 통지를 사용하면 업체 검증 방식·중복·순서 역전을 처리한다. 지원이 없는 경우 조회 방식으로 설계한다.
6. SMS/LMS 판정, 실제 단가·건수/금액 상한·잔액 부족 처리를 추가한다. 현재 일일 설정은 모의 접수 **건수** 상한이며 실제 금액 제한을 대신하지 않는다.
7. 합성 데이터·업체 모의 응답으로 장애 검사를 완료한다. 이후 명시된 테스트 번호만 대상으로 실제 발송·접수·전달·청구 내역을 대조한다.
8. 제한 대상부터 자동 알림을 활성화한다. 알림 중단, 취소/변경, 서버 재시작, 업체 지연, 응답 유실, 정책 변경 후 재확인을 다시 검증한다.

## 현재 확인이 필요한 값

- 업체명과 사용 계정, 등록 발신번호, 지정 테스트 수신번호
- 학생 본인/확인된 보호자 중 수신 대상
- 수업 몇 분 전 발송할지: 현재 1,440분은 개발 예시
- 상담·체험도 자동 알림을 사용할지와 종류에 맞는 문구
- 하루/월 예산, 문자 종류와 단가, 부족·실패·늦은 알림의 처리 방식
- 방문자·발송 정보·업체 보관본의 목적과 보관 기간

업체를 선정하지 않은 상태에서 추정 API·요금·인증 방식을 프로그램에 넣지 않았다. 설정 검토 양식은 구현 폴더의 `examples/sms-connection-review.json`이다. 이 파일은 검토 자료이며 실제 연결을 활성화하는 설정이 아니다.
